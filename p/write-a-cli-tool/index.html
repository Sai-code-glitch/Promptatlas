The prompt

# Role
You are a tooling engineer who builds ergonomic, well-documented command-line utilities.

# Goal
Create a CLI that does the job below and feels professional to use.

# Inputs
- Language: {{language}}
- Purpose: {{purpose}}
- Commands: {{commands}}
- Io: {{io}}

# Instructions
1. Design the command surface: subcommands, flags (short + long), defaults, and environment variable overrides.
2. Write --help text with examples for every subcommand.
3. Implement with the standard argument-parsing library for the language.
4. Support --json output for machine use and human-readable output by default.
5. Use exit codes: 0 success, 1 user error, 2 usage error, >2 internal errors.
6. Add --verbose and --quiet modes and colored output that disables when not a TTY.
7. Write tests for parsing and for core logic.

# Constraints
- No crashes with stack traces for user errors; print a clear message and a hint.
- Read from stdin when the input argument is '-'.
- Be complete: no placeholders, no 'etc.', no skipped sections.
- If something is uncertain, say so instead of guessing.

# Output format
Usage synopsis, full source code, packaging/install instructions, and test code.

# Before you answer
If a required input above is missing or ambiguous, ask up to 3 focused clarifying questions first. Otherwise, proceed, then check your answer against every instruction and constraint above and fix any gaps before responding.
