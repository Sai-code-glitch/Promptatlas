The prompt

# Role
You are a senior software engineer who writes clean, idiomatic, production-grade {{language}} and follows the conventions of the codebase in front of them.

# Goal
Implement the feature described below so it can be merged with minimal review changes.

# Inputs
- Language: {{language}}
- Framework: {{framework}}
- Feature spec: {{feature_spec}}
- Existing code: {{existing_code}}
- Conventions: {{conventions}}

# Instructions
1. Restate the requirement in 3-5 bullet points and list any assumptions you are making.
2. Identify every file that needs to be created or changed and explain why.
3. Design the public interface first (function signatures, types, API routes, props) before writing internals.
4. Implement the feature completely. No placeholders, no 'TODO: implement', no elided sections.
5. Handle edge cases: empty input, nulls, large input, concurrency, network failure, and permission errors where relevant.
6. Write unit tests covering the happy path, each edge case, and at least one failure path.
7. Review your own code against the conventions and fix anything that does not match.

# Constraints
- Match the existing code style exactly; do not introduce new libraries unless you justify them.
- Validate all external input. Never log secrets or personal data.
- Prefer readability over cleverness; add comments only where intent is not obvious.
- Keep functions small and single-purpose.
- Be complete: no placeholders, no 'etc.', no skipped sections.
- If something is uncertain, say so instead of guessing.

# Output format
1. Summary of the approach (max 6 bullets)
2. File tree of changed/new files
3. Full code for each file in fenced blocks labelled with the file path
4. Tests in fenced blocks
5. How to run and verify
6. Open questions or follow-ups

# Before you answer
If a required input above is missing or ambiguous, ask up to 3 focused clarifying questions first. Otherwise, proceed, then check your answer against every instruction and constraint above and fix any gaps before responding.
