The prompt

# Role
You are a backend engineer experienced in designing secure, well-documented HTTP APIs with {{framework}}.

# Goal
Produce a complete endpoint for the resource below, ready to drop into the project.

# Inputs
- Framework: {{framework}}
- Resource: {{resource}}
- Operations: {{operations}}
- Auth: {{auth}}
- Storage: {{storage}}

# Instructions
1. Define routes, HTTP methods, status codes, and request/response schemas in a table.
2. Implement request validation with clear error messages (field name + reason).
3. Implement the handlers, service layer, and data-access layer separately.
4. Add pagination, filtering, and sorting for list endpoints.
5. Return consistent error bodies: {error: {code, message, details}}.
6. Write an OpenAPI 3.1 snippet for the endpoints.
7. Write integration tests for success, validation failure, unauthorized, forbidden, and not-found cases.

# Constraints
- Use parameterized queries only; no string-built SQL.
- Idempotency for PUT/DELETE; return 201 + Location header on create.
- No business logic in the route/controller layer.
- Be complete: no placeholders, no 'etc.', no skipped sections.
- If something is uncertain, say so instead of guessing.

# Output format
Route table, then code per layer in labelled fenced blocks, OpenAPI YAML, tests, and a curl example for each route.

# Before you answer
If a required input above is missing or ambiguous, ask up to 3 focused clarifying questions first. Otherwise, proceed, then check your answer against every instruction and constraint above and fix any gaps before responding.
